# Mini Project: AI IT Helpdesk Agent

The user can ask things like:

> “My VPN is not connecting.”  
> “I forgot my password.”  
> “My laptop is very slow.”  
> “Create a support ticket for this issue.”

The system will use:

text
LLM
+
LangGraph State
+
Routing
+
Tools
+
Agent-style decision making


LangGraph is designed for exactly this kind of workflow: break the process into nodes, share state between them, and define how execution moves from one node to another. [Docs by LangChain](https://docs.langchain.com/oss/javascript/langgraph/thinking-in-langgraph?utm_source=chatgpt.com)

# 8. Node 1 — LLM classifier

This is the first AI node.

python
def classify_issue(
    state: HelpdeskState
):

    query = state["user_query"]

    prompt = f"""
Classify this IT support request.

Request:
{query}

Choose exactly one category:

password
vpn
general

Return only the category name.
"""

    response = model.invoke(prompt)

    issue_type = response.content.strip().lower()

    return {
        "issue_type": issue_type
    }


Example:

text
"My VPN won't connect"

        ↓

LLM

        ↓

vpn

# 9. Create routing function

Now we decide which tool node should run.

python
def route_issue(
    state: HelpdeskState
):

    issue_type = state["issue_type"]

    if issue_type == "password":
        return "password"

    elif issue_type == "vpn":
        return "vpn"

    else:
        return "general"


This function is our:

text
Conditional Router

# 13. Final LLM Response Node

This is where the LLM converts the tool output into a natural response.

python
def generate_response(
    state: HelpdeskState
):

    prompt = f"""
You are an IT Helpdesk Assistant.

User Issue:
{state['user_query']}

Troubleshooting Information:
{state['tool_result']}

Give a short, clear,
professional answer to the user.

Do not invent additional technical details.
"""

    response = model.invoke(prompt)

    return {
        "final_response":
        response.content
    }

# 17. Add conditional routing

builder.add_conditional_edges(

# 23. Why this is already Agentic

This is more than a normal sequential workflow because:

text
LLM interprets user request
        ↓
System decides route
        ↓
Different tool/function is selected
        ↓
Result goes back to LLM
        ↓
Final answer generated


That is the beginning of an agentic pattern.

But technically, this version is still a *controlled LangGraph workflow*, not a completely autonomous agent.

That distinction is useful for students.

# 24. Next upgrade — actual tools

After this works, convert:

text
password_help()
vpn_help()
general_it_help()


into LangChain tools using:

python
from langchain.tools import tool


For example:

python
@tool
def vpn_help() -> str:
    """
    Get troubleshooting instructions
    for VPN connection problems.
    """

    return """
    1. Check internet connection.
    2. Restart VPN.
    3. Verify credentials.
    4. Reconnect.
    """


Then we move from:

text
Graph manually selects functions


to:

text
LLM decides which tool to call


That is the next major step.

# 25. Then add a real Agent Node

The architecture will evolve into:

text
                  USER
                   ↓
                AGENT
                   ↓
              Needs Tool?
             /          \
           YES           NO
            ↓             ↓
         ToolNode       Answer
            ↓
           Agent
            ↓
           END


This is the classic tool-calling loop.

Current LangGraph documentation explicitly positions custom LangGraph workflows as the option when you want fine-grained control over agents and routing, while simpler agents can be built with higher-level LangChain agent abstractions. [Docs by LangChain](https://docs.langchain.com/oss/python/learn?utm_source=chatgpt.com)
